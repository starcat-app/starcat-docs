## 用来做什么

每个仓库可以有一份**只在本机**的笔记，用来记「为什么 Star、踩过什么坑、准备怎么用」。正文进本地搜索，GitHub 上的协作者看不到。

状态只有三档，用来分诊而不是当看板：

| 状态 | 含义 |
|------|------|
| **未读 unread** | 还没处理；新 Star 常见默认 |
| **已读 read** | 看过 README / 已经了解 |
| **正在使用 using** | 项目里真正在用 |

旧文案里的「在读 / 废弃」已经不用。

## 怎么写笔记

1. 选中仓库，右侧打开「私有笔记」
2. 编辑 Tab 写 Markdown，可切预览
3. 看自动保存指示；写入本地 SQLite

插件或 MCP/CLI 写入成功后，详情会刷新。

**AI 生成（Pro）：** 笔记区头部「AI 生成」先出草稿，**确认后才保存**，不会覆盖你没点确认的正文。见 [AI 个人笔记](/zh-Hans/ai-features/personal-notes)。

## 怎么改状态

详情里：未读 / 已读胶囊点一下进入「正在使用」；正在使用点 × 回到已读。

筛选见 [筛选](/zh-Hans/search/filters)。配对 CLI：

```bash
starcat repo status set owner/repo using --apply
```

见 [CLI](/zh-Hans/cli/usage)。

标成「正在使用」时，可能会问要不要入库，方便 RAG。入库、Star、状态三者独立。见 [入库](/zh-Hans/knowledge-base/adding-repos)。

## 注意

- 笔记不进 GitHub，换机器靠 [备份](/zh-Hans/data-privacy/backup)。
- 没保存的草稿不会被列表搜索到。
