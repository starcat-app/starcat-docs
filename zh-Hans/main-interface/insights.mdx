## 用来做什么

洞察有两层：

- **我的洞察**：整个 Stars 库或知识库「整理得怎么样、技术栈怎么分布、有哪些该处理」
- **仓库洞察**：当前这个仓最近在忙什么、健不健康、有没有安全公告

生成后的洞察可以挂到 AI 摘要、仓库对话和 RAG 上当只读上下文，用完能摘掉。

## 我的洞察

入口：侧栏 **Manage → 我的洞察**。范围可在「全部收藏」和「知识库」之间切。要点刷新时手动刷，不要假设它实时跟 GitHub 同步。

## 仓库洞察

入口：选中仓库后，详情里的洞察。依赖网络、权限和缓存，区块不一定每次都齐。

<Frame caption="截图待补充 · `images/screenshots/main-interface/repo-insights.webp`">
  <div className="rounded-xl border-2 border-dashed border-zinc-400/80 px-6 py-14 text-center text-sm text-zinc-500 dark:border-zinc-600 dark:text-zinc-400">
    仓库洞察：Star 增长、发布节奏、安全公告和 Release 附件
  </div>
</Frame>

- Star 增长与协作活动
- 提交趋势与贡献者
- 发布节奏；最新 Release 先展示前 3 个附件，可展开全部，复制链接或下载到本地
- 健康度、社区规范、安全信号
- 最近 5 条已发布安全公告：风险等级、GHSA / CVE、日期、发布者；可打开公告或 GitHub 完整列表

切仓或刷新时内容应稳住。部分 GitHub 统计会先显示「生成中」再自动重试。

[我的项目](/zh-Hans/main-interface/my-projects) 里的私仓，高权限指标走 **GitHub App** token。部分只对公开仓开放的信号可能仍没有。

## 给 AI / RAG 用

洞察生成后是**可移除的只读 XML 上下文**，可参与摘要、对话和 [RAG](/zh-Hans/knowledge-base/rag-workspace)。自定义提示词没写洞察占位符时，**不会**偷偷塞进去。不可用、未注入或回退时，界面会标明。

全局洞察聚合也会作为知识库问答的共享上下文。

## 注意

- 洞察是辅助判断，不是安全审计结论。
- 安全公告和附件需要能访问 GitHub；失败时看界面提示，不要当「没有漏洞」。
