## 用来做什么

在点进源码或开 Issue 之前，先看这个仓还维不维护、文档和安全信号如何。**Repo Health 是辅助阅读，不是安全审计报告。**

需要 [Pro](/zh-Hans/subscribe/plan-comparison)。非 Pro 点徽章会进付费墙。

## 怎么看

- 列表行上的 Health 徽章
- 详情元数据区徽章 → **Repo Health** 面板

面板常见四维（0–100，名称以 App 为准）：

- **维护**：提交 / Release 是否还活跃
- **人气**：Star、社区热度
- **质量**：文档与工程信号
- **安全**：含与 OpenSSF 的对照

可打开「评分规则」，并手动刷新。

## OpenSSF

详情可显示 OpenSSF Scorecard 徽章：悬停或点击看摘要 / 雷达；完整 checks 进 Sheet。

<Frame caption="OpenSSF Scorecard">
  <img src="/images/screenshots/openssf.webp" alt="OpenSSF 评分" className="rounded-xl" />

数据依赖网络和缓存。失败时看界面错误，不要当成「0 分」。

## 筛选与插件

工具栏可筛「已有 Health / OpenSSF 缓存」的仓，见 [筛选](/zh-Hans/search/filters)。

浏览器插件只展示**本机已缓存**的只读分数，不会在 GitHub 网页上重算一整遍。见 [插件功能](/zh-Hans/browser-plugin/features)。

## 注意

- 私仓上部分 OpenSSF 路径可能不可用，见 [我的项目](/zh-Hans/main-interface/my-projects)。
- 目录型 GitHub Issue Forms 会按社区规范识别，不再误标成「缺失」。
