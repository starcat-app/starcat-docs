## Purpose

The knowledge base is the set of repositories you ingest so the RAG workspace can retrieve and answer. Starring a repo does not ingest it.

## Stars vs knowledge base

| | Stars | Knowledge base |
|--|-------|----------------|
| Source | GitHub star sync | You mark ingest in Starcat |
| Scale | Thousands is normal | Curate (often dozens to a couple hundred) |
| List search | Yes | Yes (can limit to knowledge) |
| Default RAG scope | No | Yes, ingested only |
| Typical index | FTS and similar | Chunks + keywords + vectors |

- Star does not auto-ingest
- Unstar does not auto-remove from the library
- Ingested but not starred: still askable, and you can still [subscribe to Releases](/release/subscription)

## What you need

1. [Pro](/subscribe/plan-comparison)
2. Chat + Embedding → [AI configuration](/ai-features/configuration)
3. Some ingested repos → [Adding repos](/knowledge-base/adding-repos)

Without Embedding the workspace may open, but vector retrieval cannot build. See [Index management](/knowledge-base/index-management).

## Capability map

| I want to… | Go here |
|------------|---------|
| Put a repo in the library | [Adding repos](/knowledge-base/adding-repos) |
| Ask a question | [RAG workspace](/knowledge-base/rag-workspace) (⇧⌘K) |
| Open the cited source | [Citations](/knowledge-base/citations) |
| Manage history | [Sessions](/knowledge-base/session-management) |
| Fix low coverage | [Index management](/knowledge-base/index-management) |

Suggested path: ingest 20-50 repos (prefer **using**) → confirm Embedding and coverage → @ one repo first → then ask across repos.

Entries: sidebar Manage → Library; toolbar Knowledge Q&A or **⇧⌘K**; knowledge-related Smart Collections.

## Notes

- [Semantic search](/search/semantic-search) is list-level vector search, not workspace Q&A.
- Ingesting everything you starred stretches index time and the Embedding bill.
