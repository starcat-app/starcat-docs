## Purpose

In **Settings → Extensions & Connections → MCP**, enable the [CLI](/cli/installation) and MCP clients to call Starcat capabilities. The service requires [Pro](/subscribe/plan-comparison). Reads are on by default. Use **Allow Writes** for operations such as updating a note or running an evaluation. CLI commands with a preview require `--apply` to execute.

## How to use it

1. Enable MCP Service
2. Confirm the port (often 5555; avoid clashes)
3. Turn on **Allow Writes** if the client needs to run write capabilities
4. Copy the terminal pairing command and run it on the Mac running Starcat. To pair another device, enable **Allow Other Devices**, then copy **Pair from Another Device** and run it there.

```bash
starcat pair "starcat-pair://connect?..."
starcat doctor
```

The URI lasts about 5 minutes and can be used once. Confirm the device in the app. The CLI stores the device token in the operating system's credential store. See [CLI usage](/cli/usage).

## Local and network addresses

On Starcat builds with HTTP-only listening, the local MCP address is `http://127.0.0.1:5555/mcp` with **Allow Other Devices** on or off. The setting adds a network address on the same port. Use the address shown in MCP settings. For a different device, use the Mac's `.local` name if it resolves there, or the Mac's current network IPv4 address for direct HTTP requests.

For cross-device pairing, use the HTTP-only App build with a CLI v3 build. Run `starcat doctor` after updating. If the saved host and port respond over HTTP with the existing device credential, the CLI updates the address automatically. If the host or port changed, copy a fresh pairing command. Restart running `starcat mcp` processes after the update.

The settings page can copy a full setup prompt for an agent, and it checks the CLI version before install, updating it when needed. Paired devices show the pairing date so you can tell a new machine from an old one.

Agents can read repositories, notifications, releases, the knowledge base, and models. Tag, note, Star, and Unstar writes still go through confirmation and the audit log. See [CLI usage](/cli/usage).
