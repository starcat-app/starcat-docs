## What they are for

Each repository can have a **local-only** note: why you starred it, what broke, how you plan to use it. The body is indexed for local search. Collaborators on GitHub never see it.

Status is a three-value triage, not a kanban:

| Status | Meaning |
|--------|---------|
| **unread** | Not handled yet; common default for new Stars |
| **read** | You have seen the README / you understand it |
| **using** | You actually depend on it in a project |

Older labels such as “reading / deprecated” are gone.

## Notes

1. Select a repo and open **Private notes** on the right
2. Write Markdown on the Edit tab; switch to Preview as needed
3. Watch the autosave indicator; it writes local SQLite

Successful writes from the browser extension or MCP/CLI refresh the pane.

**AI generate (Pro):** **Generate with AI** in the notes header produces a draft. **Nothing is saved until you confirm.** See [AI personal notes](/ai-features/personal-notes).

## Status

In detail: tap unread / read to enter **using**; tap × on using to return to read.

Filter via [Filters](/search/filters). After CLI pairing:

```bash
starcat repo status set owner/repo using --apply
```

See [CLI](/cli/usage).

Marking **using** may ask whether to ingest for RAG. Ingest, Star, and status are independent. See [Ingest](/knowledge-base/adding-repos).

## Notes

- Notes are not on GitHub. Moving Macs requires [backup](/data-privacy/backup).
- Unsaved drafts are not list-searchable.
