## What they are for

Tags are Starcat’s usual **on-device classification**: you pick color, icon, and name. They never leave this Mac. GitHub Stars Lists match GitHub’s own grouping; tags match *your* scheme (`frontend/react`, `ops/k8s`).

Cross-device cloud sync is not shipped. [Back up](/data-privacy/backup) before you move machines.

<Note>
  Free: **20** tags. Pro: unlimited. See [Plans](/subscribe/plan-comparison).
</Note>

## Create a tag

1. Tap “+” next to Tags in the sidebar, or open tag management
2. Set name, color, and SF Symbol
3. Save; you can apply it immediately

Hitting the free cap is gated with a Pro prompt.

## Apply tags

**One repo:** [Repository detail](/main-interface/repo-detail) → tag area → search and multi-select. Applies immediately.

**Many repos:** [Multi-select](/manage-stars/batch-operations) → Tags on the bottom bar. Batch **appends**; it does not clear existing tags.

Click a tag in the sidebar to list only those repos. Toolbar filters can narrow by tag too. See [Filters](/search/filters).

## Edit and delete

Context menu: rename, recolor / icon, delete. Deleting a tag **does not delete repositories**; it only drops the association.

## AI suggestions (Pro)

Repo AI can suggest 3–8 tags; **nothing is written until you confirm**. See [Tag recommendations](/ai-features/tag-recommendation). Keep your own naming first so AI fills the existing system instead of exploding the vocabulary.

## Notes

- Too many tags make filters worse. Dozens of good ones beat hundreds of one-offs.
- Do not 1:1-map Lists to tags. Lists follow GitHub; tags follow you.
